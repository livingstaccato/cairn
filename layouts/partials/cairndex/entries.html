{{- /* Returns every cairndex entry across the site as neutral maps, for a host site to fold into its own search index. Keys are deliberately generic: cairndex does not own any search engine's record shape. The two known consumers disagree — a Fuse index wants {title,url,content,tags,date,excerpt}, a knowledge-corpus index wants {title,summary,kind,source_path,url,text} — so owning either would be wrong for the other. Usage in a host's layouts/index.json: {{- range partial "cairndex/entries.html" . -}} {{- $idx = $idx | append (dict "title" .title "url" .path "content" .summary "tags" .tags "date" .modified "excerpt" .summary) -}} {{- end -}} Pages are found by the presence of .Params.cairndex rather than by layout: cairndex writes branch bundles, which site.RegularPages does not include. Entries themselves come from each page's own index.json resource, via cairndex/entries-data.html, not from .Params.cairndex.entries — that field does not exist. Hugo refused any directory past roughly ten thousand entries while the listing rode in frontmatter, so cairndex moved it into a bundle resource instead; this partial predates that move and silently returned nothing for every page from the moment it landed until ci/templates.sh started rendering a real search-integration host and reading back what it got. */ -}} {{- $out := slice -}} {{- range site.Pages -}} {{- $page := . -}} {{- with .Params.cairndex -}} {{- $section := .path -}} {{- $entries := partial "cairndex/entries-data.html" $page -}} {{- range $entries -}} {{- $out = $out | append (dict "title" (.title | default .name) "path" .path "summary" (.summary | default "") "tags" (.tags | default slice) "modified" .modified "kind" .kind "section" $section) -}} {{- end -}} {{- end -}} {{- end -}} {{- return $out -}}
